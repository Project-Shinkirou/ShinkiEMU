# ユーザーガイド

## インストールと起動

[ShinkiEMU Releases](https://github.com/Project-Shinkirou/ShinkiEMU/releases) から、お使いのプラットフォームとアーキテクチャに合った Manager の成果物をダウンロードします。デスクトップ版のパッケージは書き込み可能なディレクトリにすべて展開し、`shinki-emu-manager`（Windows では `.exe`）を実行します。同梱の依存ファイル、ライセンス、リソースはそのまま残してください。デスクトップでは `shinki-emu-manager --help` でヘルプを表示でき、サブコマンドなしで起動すると GUI が開きます。

ダウンロードするのは Release に実際に添付されているファイルだけにしてください。ビルド状況は[コア一覧](https://project-shinkirou.github.io/ja/shinkiemu/cores/)で確認できます。Android の debug 署名付き CI APK はテスト用パッケージです。iOS は実機向けとシミュレーター向けの成果物を区別する必要があり、ライブラリファイルはインストール可能な IPA ではありません。

初回起動時に、ゲームフォルダーの追加、ネットワーク接続、外観を設定できます。設定はスキップでき、ネットワーク接続は初期状態ではオフです。ShinkiEMU は無料のオープンソースソフトウェアです。公式サイトや GitHub Releases から入手してください。ライセンスは「設定 → 情報」で確認できます。

「設定 → 情報 → 謝辞」では、上流コア、サードパーティー製コンポーネント、貢献者を分けて表示します。各コアのサイトとライセンスは別々に開けます。Android の「情報 → サードパーティーライセンス」では同梱の通知とライセンスをアプリ内で読めます。デスクトップでは従来どおりシステムで通知ファイルを開きます。

Android の「情報 → 診断ログを共有」では、最近の診断ログの要約をシステムの共有画面で渡せます。元のログは添付されず、自動アップロードも行いません。デスクトップのデータフォルダーとログフォルダーを開く操作は従来どおりです。

## 表示言語

Manager は簡体字中国語、英語、日本語で表示できます。「設定 → 外観 → 言語」で切り替えてください。「システムに従う」を選ぶと OS の言語に合わせ、中国語環境では簡体字中国語、日本語環境では日本語、それ以外では英語で表示します。切り替えはすぐに反映され、ほかの設定と一緒に保存されます。中国語と日本語のフォントを同梱しているため、CJK フォントのないシステムでも正しく表示されます。漢字は日本語表示では日本語の字形、それ以外では簡体字中国語の字形で描画します。

ゲームのタイトル、説明、パッチの説明はメタデータから取得します。現在の言語の内容を優先し、日本語がない場合は英語、英語もない場合は簡体字中国語を表示します。

## Manager の更新

ネットワーク接続を許可すると、Manager は起動時に一度、バックグラウンドで自身の更新を確認します。起動を妨げず、失敗してもダイアログは表示しません。「設定 → アップデート → 今すぐ確認」では手動で確認し、失敗の理由を表示します。Project-Shinkirou/ShinkiEMU の GitHub Releases にある `manager-v<semver>` タグを比較します。コアやストアのゲームの更新とは別の機能です。

プレリリース版を受け取るか選択でき、現在の Manager がプレリリース版なら初期値はオンです。新しい版が見つかると、バージョン、リリースノート、現在のプラットフォーム向けダウンロード先を表示し、システムのブラウザーで開きます。自動ダウンロードや自動インストールは行いません。無視したバージョンは端末に保存され、再通知しません。「後で」は今回のセッションだけ通知を隠します。オフライン時は更新リクエストを送信しません。

## ゲームの追加とコアのインストール

ライブラリ上部の「フォルダーを追加」アイコンで、元のゲームフォルダーを選びます。ファイルはコピーせず、そのままスキャンします。オフラインでも、コアのインストール前でもゲームを検出できます。追加時のダイアログでは進捗を確認し、スキャンを中止できます。バックグラウンド更新の進捗は一覧の上に表示されます。Android でアクセスを求められたら、システムのフォルダー選択画面で許可してください。

Android 11 以降では、初回設定のフォルダー画面からも「すべてのファイルへのアクセスを許可」を選べます。許可は任意で、Android のシステム設定で行います。

タッチ画面では、ゲーム一覧の先頭から下に引いて指を離すと再スキャンできます。ネットワーク接続を許可している場合は、メタデータも同期します。フォルダーの管理やキーボードでの更新は「設定 → ライブラリフォルダー」から行えます。

Android 11 以降では、対応コアがファイルを直接読み取る必要がある場合に「設定 → ライブラリフォルダー → 共有ストレージへのアクセスを許可」を選びます。共有ストレージ上の全ファイルへのアクセスを許可するかは、システム設定で選択できます。フォルダー選択画面で許可したフォルダーは引き続きスキャンできます。ゲームカードに斜線入りのフォルダーアイコンが表示されている場合、コアはそのフォルダーを直接読み取れません。ゲームを選ぶと詳細に理由が表示されます。

上部の「検索」、または **Ctrl+F** で検索できます。タイトルを入力すると一覧が更新され、ゲームを選ぶと詳細が開きます。「絞り込みオプション」で互換性による絞り込み、並べ替え、表示形式の変更、検索と絞り込みの解除ができます。

コアがないため起動できない場合は、対応するコアをインストールし、必要に応じて再起動します。候補のエンジンやコアが複数ある場合は、使うものを選択します。コアが一時的に見つからなくなっても、選択は保持されます。

ライブラリとコア一覧は静的カタログと検証済みのパッケージ manifest を使います。高度な設定の準備、コアの明示的な診断、ゲームの起動でのみ、owner スレッドが選択した実装の設定・機能を調べます。識別は実行互換性を保証しません。暗号化されたリソースに必要な秘密鍵はローカルに保管してください。

コアの更新で廃止された設定は、保存済みの設定から自動的に削除されます。

メタデータの同期やコアのダウンロードの前に、設定でネットワーク接続を許可します。コア管理ページでカタログを更新し、現在のプラットフォーム向けのコアをインストールまたは更新します。カタログにはバージョン、ABI、ダウンロード URL、ハッシュが記録されています。読み込み済みのライブラリを置き換える更新では、先にセッションを終了し、画面の指示に従って Manager を再起動してください。コアディレクトリは `core.json`、依存ファイル、存在する場合は `Resources/`、ライセンスを含めて丸ごと保持してください。DLL だけをコピーしてもインストールにはなりません。

## ストアからのダウンロード

設定でネットワーク接続を許可し、ライブラリ上部の「ダウンロード」を選びます。複数のストアを組み込んだ場合は、先にストアを選びます。ログイン方法はストアごとに異なります。Steam は QR、アカウントとパスワードによる Steam Guard 認証、デスクトップクライアントからのインポートに対応します。DLsite と DMM/FANZA は Manager 内でストア自身のサインインページを開きます。Cookie と更新 token はシステムの秘密情報ストアだけに保存され、インストール記録やログには書き込まれません。ログアウトすると、そのストアの保存済みログインが削除されます。

**Web サインイン（DLsite、DMM/FANZA）：**「サインインページを開く」を選ぶと、ストア公式のサインインページをシステムの Web ビューで表示します。Windows は WebView2、macOS と iOS は WKWebView、Linux は WebKitGTK の別ウィンドウ、Android はアプリの上に WebView を表示します。CAPTCHA や二段階認証も含め、そのページでサインインしてください。ストアがアカウントのセッション付きでサインイン後のページに進むと、Manager は Web ビューからそのストアの Cookie（HttpOnly Cookie を含む）を直接読み取り、ページを閉じてログインを完了します。コピーや貼り付けは不要です。Web ビューは毎回空のプライベート Cookie ストアで始まり、閉じた後には何も残しません。保存されるのはストアのログイン情報だけで、保存先はシステムの秘密情報ストアです。「キャンセル」、ウィンドウを閉じる、Android の戻る操作、ストア画面から離れる、のいずれでもサインインは中止されます。Windows では Microsoft Edge WebView2 ランタイム（Windows 11 は標準搭載）、Linux では WebKitGTK 4.1（`libwebkit2gtk-4.1`）が必要です。

**Steam のログイン：**アカウント名とパスワードでログインし、案内に従ってメールまたはモバイルの Steam Guard コードを入力するか、スマートフォンで承認します。Steam モバイルアプリでローカル生成された QR コードをスキャンする方法もあります。デスクトップ版では Steam クライアントのキャッシュ済みログインも取り込めます。モバイル版はパスワードまたは QR コードでログインします。パスワードは保存されません。リフレッシュトークンはシステムのシークレットストア（Windows 資格情報マネージャー、Linux Secret Service、macOS/iOS のキーチェーン、AndroidKeyStore で暗号化されたアプリ専用ストレージ）にだけ保存されます。ログアウトすると保存済みのログイン情報は消去されます。

「QR コードでログイン」を選ぶと、アカウント名やパスワードを入力せずに、新しいログイン用 QR コードを Steam に要求します。Steam の応答後に QR コードが表示され、モバイルアプリで承認するとログインが完了します。キャンセルすると待機を止め、ログインは完了しません。

所有ゲーム、デポ、ブランチ、書き込み可能な保存先を選びます。Windows 向けデポはモバイル版でも既定で選択され、言語デポは個別に選べます。ダウンロード後も同じネイティブ実行なしの識別を行い、識別できたディレクトリだけを登録します。ダウンロード可能であっても実行互換性は保証されません。

「更新を確認」は、ローカルと Steam のデポマニフェストを比較します。再度ダウンロードすると、変更のないローカルデータを再利用して差分更新を行います。「検証と修復」はインストール済みのファイルを検証し、修復します。キャンセルすると、進行中の書き込みが終わるのを待ち、中断マーカーを残します。再試行時は検証済みのローカルチャンクを再利用して続行します。各ゲームディレクトリの `.DepotDownloader` は削除しないでください。インストール済みのマニフェストと差分更新に必要な情報が記録されています。

ダウンロードできるのは、ログイン中のアカウントが所有する PC ダウンロード版だけです。Play 専用、ストリーミング、ブラウザ向け作品にはダウンロードできない理由を表示します。DRM、起動 token、ライセンス確認は回避しません。ブランチ、デポ、検証の操作はストアが対応する場合だけ表示します。新規インストールは `<ライブラリ>/.shinki/store/<provider>/installs/`、一時ファイルとキャッシュは `<Manager データディレクトリ>/.shinki/store/<provider>/` に保存します。以前の Steam インストール記録と秘密情報ストアの参照は一度だけ移行し、ゲーム本体は移動しません。

ストアがインストール済みのバージョンを判定できない場合は、エラーではなく **Update status unavailable** と表示し��更新操作を非表示にします。ライブラリを更新すると再確認します。アーカイブやインストーラーをダウンロードした場合は、完了後に **Downloaded archives need manual extraction or installer run** と **Open folder** を表示します。自分で展開するか公式インストーラーを実行し、実際に起動できるゲームディレクトリを Manager に追加してください。インストーラーや DRM の回避は行いません。


## DLsite ダウンロード

DLsite は上記の Web サインインを使い、DLsite Play のログインページから始めます。DLsite が `__DLsite_SID` のアカウントセッション付きで Play に戻るとサインイン完了です。セッションはプラットフォームの秘密情報ストアだけに保存されます。ライブラリには DLsite Play の購入作品を表示し、DLsite がアカウント向けに提供する PC 版ファイルだけを取得します。Play の閲覧用・メディア用最適化ファイルはゲームとしてインストールしません。ZIP はパス安全性を検査して展開します。RAR と自己解凍インストーラーは変更せず保存し、手動での展開またはインストールが必要です。ダウンロードした実行ファイルを Manager が起動することはありません。調査した API からはインストール済みビルドを特定できないため、更新状態は不明として表示します。

ダウンロード計画を解決できない作品は、サインイン済みブラウザーで操作を再現し、応答本文を含む HAR をエクスポートしてください。`https://play.dlsite.com/api/v3/download?workno=<購入済み作品番号>` から始め、リダイレクト先と `/home/download`、`/home/serial`、分割ファイル一覧の各リクエストを含めます。共有前に Cookie、シリアル番号、署名付き URL の token を削除してください。HAR をコミットしないでください。

## 互換性とメタデータ

既定のメタデータソースは次のとおりです。

`https://project-shinkirou.github.io/data/shinkiemu/v1/`

設定ページでネットワーク接続の許可と手動同期を行えます。破損した、または検証に通らなかったスナップショットが有効なキャッシュを上書きすることはありません。レポートを見るときは、VNDB のリリース rID、コア、プラットフォーム、アーキテクチャ、desktop/device/simulator のバリアントがすべて一致しているかを確認してください。別のプラットフォームやアーキテクチャの結果は、現在の環境には当てはまりません。再現可能な観察結果は [issue フォーム](https://github.com/Project-Shinkirou/ShinkiEMU/issues/new/choose)から報告できます。

## 映像フィルター

Manager の **フィルター**、またはゲーム内メニューの **画面フィルター**を開きます。**フィルターを追加**で末尾に追加し、行を選んでパラメーターを調整できます。矢印で順番を変え、ごみ箱で削除します。フィルターは表示順に適用されます。**チェーンを置換**でプリセットを選ぶとチェーン全体が置き換わり、**オリジナル**を選ぶとすべてのフィルターが外れます。

**フィルターを追加 → HLSL エフェクトを読み込む…** から Magpie 形式 4 のエフェクトを追加できます。HLSL エフェクトには DXC が必要です。GPU フィルターに対応していない場合や、HLSL を使うフィルターに必要な DXC がない場合は、一覧に理由が表示されます。

## パッチ

**オンラインのパッチ**でレビュー済みの Luau パッチを選ぶか、**ローカルのパッチを読み込む…**で `.luau` スクリプトまたは ZIP を開きます。カタログに紐付かないローカルスクリプトは未レビューと表示します。オンラインパッチは具体的なリリースに紐付き、書き込み前にファイル指紋を確認します。スクリプトは明示的に選択した場合だけ実行されます。ダウンロードは HTTPS に限定し、宣言したサイズと SHA256 を確認して `<game>/.shinki/patch/` に保存します。オンライン記録では宣言済みのダウンロードだけを許可します。

既定の**新しいディレクトリ**では元のゲームを変更せず、セーブをコピーしません。**その場で上書き**は専用の一時領域へ書き込み、変更・削除する元ファイルを `<game>/.shinki/backup/<id>/` に退避して、`manifest.json` にハッシュを記録します。**最新のパッチを復元**は、ユーザーが後から編集したファイルを上書きしません。レシートは `<game>/.shinki/patch-result.json` に保存します。リソースパッチは EXE を作成・変更できません。貢献方法は [Metadata](metadata.md) を参照してください。

Windows では、出力・作業用・バックアップの各ディレクトリは親ディレクトリのアクセス権を継承します。出力先には信頼できる親ディレクトリを選び、その場で上書きする場合も信頼できるゲームディレクトリを使ってください。書き込み権限を持つ他のプロセスから作業中のファイルを隔離するものではありません。

Windows、macOS、Linux の**新しいディレクトリ**モードでは、出力先の選択にフォルダーピッカーを使います。変換結果を置く親フォルダーを選んでください。システムのフォルダー操作で新しいフォルダーを作ることもできます。Manager は、その中に作成する `localized-output` のフルパスを表示します。同名の項目がある場合は `localized-output-1`、`localized-output-2` などを提案します。開始前にこのパスを確認してください。選択だけでは変換用ディレクトリを作成せず、変換成功時に結果を公開します。選択のキャンセルは以前のパスを変更しません。既存のファイルやディレクトリは上書きせず、選択後に他のプログラムが出力パスを使用した場合も拒否します。出力先はゲームやパッチ入力先と重複できません。**その場で上書き**では出力先の選択を使用しません。iOS では選択した親フォルダー内に新しい `localized-output` を作成し、Android ではアプリ専用の新しいエクスポートディレクトリを使います。

Windows のマップされた入力フォルダー（読み取り専用の Sandbox 共有を含む）は、ネイティブハンドルから取得したファイル ID で重複を確認します。拡張 `FileIdInfo` クエリが未対応エラー 50 を返す場合だけ、`GetFileInformationByHandle` の ID を使います。他のエラーでは変換を中止します。パッチウィザードは verbatim 接頭辞が不要な場合に通常の Windows パスを表示します。保存済みのゲーム ID とハンドルに基づくディレクトリ境界の検査は変更しません。

新しい Musica パッチにはコア beta.5 以降が必要で、Yorino は機能ビット 256 と 512 を必要とします。RFVP のネイティブスクリプトパッチにはセーブ分離と設定フォントの優先が必要です。インポートではコアをロードせず receipt の設定を保存し、高度な設定の明示的な準備や起動時に選択コアの実際の descriptor で設定・機能を検証します。失敗しても登録項目と receipt は保持し、必要な修正やコア更新を表示します。バージョン名だけで機能を判断しません。旧 Manager は v1 カタログと旧スクリプトを読み込みます。

変換結果の receipt が未適用の間は、別の作品用にコアがロード済みでも高度な設定は未準備と表示されます。「設定を読み込む」で対象作品と選択コアの設定を検証・保存します。成功時に保留設定を一度だけ消費し、失敗時は従来の設定と receipt を保持して再試行できます。

## データとセーブ

ShinkiEMU は新しいプラットフォーム別のアプリケーションデータディレクトリを使い、その場所は設定から開けます。デスクトップでは `SHINKI_EMU_DATA_DIR` で絶対パスを指定できます。Android ではアプリ専用ディレクトリを使います。名称変更前のアプリケーションデータベース、キャッシュ、製品独自のセーブは自動では取り込まれません。この切り替えで元のゲームのインストールや市販版のセーブデータが変更されることはありません。

セーブの扱いはコアごとに決まります。[Musica](cores/shinki-emu-musica.md) は `<game>/.shinki/musica/minori/<title>/` の eden/Perseus 形式の `.sav` と `.png` を使います。旧 beta の `.asav` は非対応で、読み込みも変更も変換も行いません。ReMinori の保存先は別です。バックアップや互換性のあるオリジナル形式のファイル交換は、実行中のセッションを終了してから行ってください。
