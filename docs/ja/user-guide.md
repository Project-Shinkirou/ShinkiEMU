# ユーザーガイド

## インストールと起動

[ShinkiEMU Releases](https://github.com/Project-Shinkirou/ShinkiEMU/releases) から、お使いのプラットフォームとアーキテクチャに合った Manager の成果物をダウンロードします。デスクトップ版のパッケージは書き込み可能なディレクトリにすべて展開し、`shinki-emu-manager`（Windows では `.exe`）を実行します。同梱の依存ファイル、ライセンス、リソースはそのまま残してください。デスクトップでは `shinki-emu-manager --help` でヘルプを表示でき、サブコマンドなしで起動すると GUI が開きます。

ダウンロードするのは Release に実際に添付されているファイルだけにしてください。ビルド状況は[コア一覧](https://project-shinkirou.github.io/ja/shinkiemu/cores/)で確認できます。Android の debug 署名付き CI APK はテスト用パッケージです。iOS は実機向けとシミュレーター向けの成果物を区別する必要があり、ライブラリファイルはインストール可能な IPA ではありません。

初回起動時には、中国語と英語の転売防止に関する告知を読み、「我已阅读 / I have read this」にチェックを入れてください。告知が合計 8 秒間表示されると先へ進めるようになります。確認の記録と告知テキストの SHA-256 ダイジェストはローカルに保存され、告知が更新されると再確認が必要です。ShinkiEMU は無料のオープンソースソフトウェアです。公式サイトまたは GitHub Releases からダウンロードしてください。お金を払って入手した場合は、返金を申請し、販売者を通報してください。告知は設定の「About」ページでも確認できます。

二言語の告知は Rust で画像としてラスタライズされ、オンボーディングと「About」の画像スロットに表示されます。読了時間が加算されるのは、画像全体が読めるサイズでスクロール領域内に表示されている間だけです。非表示、サイズ不足、切り抜かれた状態、ウィンドウの最小化中は計測が止まります。ウィンドウが狭い場合は高さを広げるか、告知全体が見える位置までスクロールしてください。UI の画像を削除しても Rust 側の完了チェックは回避できず、オンボーディングは完了しません。

告知画像は現在のライトテーマまたはダークテーマ、その背景色と文字色に追従し、カスタムテーマの色も反映されます。テーマを切り替えると画像は再ラスタライズされますが、加算済みの読了時間は保持されます。

## ゲームの追加とコアのインストール

設定で、正規に入手したゲームのインストールディレクトリを追加し、ライブラリをスキャンします。ゲームを選んだら、検出されたコアとゲーム固有の設定を確認してからセッションを開始します。プローブの一致はフォーマットが認識されたことを示すだけです。暗号化されたリソースには別途プライベートな設定が必要な場合があり、鍵は常にローカルに保管してください。

コアの更新で廃止された設定は、保存済みの設定から自動的に削除されます。

メタデータの同期やコアのダウンロードの前に、設定でネットワーク接続を許可します。コア管理ページでカタログを更新し、現在のプラットフォーム向けのコアをインストールまたは更新します。カタログにはバージョン、ABI、ダウンロード URL、ハッシュが記録されています。読み込み済みのライブラリを置き換える更新では、先にセッションを終了し、画面の指示に従って Manager を再起動してください。コアディレクトリは `core.json`、依存ファイル、存在する場合は `Resources/`、ライセンスを含めて丸ごと保持してください。DLL だけをコピーしてもインストールにはなりません。

## ストアからのダウンロード

設定でネットワーク接続を許可し、「ゲームを追加 → ストアからダウンロード」を開きます。複数のストアを組み込んだ場合は、先にストアを選びます。ログイン方法はストアごとに異なります。Steam は QR、アカウントとパスワードによる Steam Guard 認証、デスクトップクライアントからのインポートに対応します。DLsite と DMM/FANZA は公式ブラウザログインと Cookie の受け渡しを使います。公式ページで自分のアカウントにログインし、そのサイトの Cookie をパスワード形式の欄に貼り付けてください。送信後に欄は消去されます。Cookie と更新 token はシステムの秘密情報ストアだけに保存され、インストール記録やログには書き込まれません。ログアウトすると、そのストアの保存済みログインが削除されます。

**Steam のログイン：**アカウント名とパスワードでログインし、案内に従ってメールまたはモバイルの Steam Guard コードを入力するか、スマートフォンで承認します。Steam モバイルアプリでローカル生成された QR コードをスキャンする方法もあります。デスクトップ版では Steam クライアントのキャッシュ済みログインも取り込めます。モバイル版はパスワードまたは QR コードでログインします。パスワードは保存されません。リフレッシュトークンはシステムのシークレットストア（Windows 資格情報マネージャー、Linux Secret Service、macOS/iOS のキーチェーン、AndroidKeyStore で暗号化されたアプリ専用ストレージ）にだけ保存されます。ログアウトすると保存済みのログイン情報は消去されます。

「QR コードでログイン」を選ぶと、アカウント名やパスワードを入力せずに、新しいログイン用 QR コードを Steam に要求します。Steam の応答後に QR コードが表示され、モバイルアプリで承認するとログインが完了します。キャンセルすると待機を止め、ログインは完了しません。

所有しているゲームを検索し、デポとブランチを選んでから、書き込み可能なライブラリディレクトリを選択します。Windows 向けデポはモバイル版でも既定で選択されています。言語デポは個別に選択できます。ダウンロードが終わると、Manager はゲームを自動で追加し、対応するコアをプローブします。ゲームをダウンロードできても、そのエンジンに対応するコアがあるとは限りません。

「更新を確認」は、ローカルと Steam のデポマニフェストを比較します。再度ダウンロードすると、変更のないローカルデータを再利用して差分更新を行います。「検証と修復」はインストール済みのファイルを検証し、修復します。キャンセルすると、進行中の書き込みが終わるのを待ち、中断マーカーを残します。再試行時は検証済みのローカルチャンクを再利用して続行します。各ゲームディレクトリの `.DepotDownloader` は削除しないでください。インストール済みのマニフェストと差分更新に必要な情報が記録されています。

ダウンロードできるのは、ログイン中のアカウントが所有する PC ダウンロード版だけです。Play 専用、ストリーミング、ブラウザ向け作品にはダウンロードできない理由を表示します。DRM、起動 token、ライセンス確認は回避しません。ブランチ、デポ、検証の操作はストアが対応する場合だけ表示します。新規インストールは `<ライブラリ>/.shinki/store/<provider>/installs/`、一時ファイルとキャッシュは `<Manager データディレクトリ>/.shinki/store/<provider>/` に保存します。以前の Steam インストール記録と秘密情報ストアの参照は一度だけ移行し、ゲーム本体は移動しません。

ストアがインストール済みのバージョンを判定できない場合は、エラーではなく **Update status unavailable** と表示し��更新操作を非表示にします。ライブラリを更新すると再確認します。アーカイブやインストーラーをダウンロードした場合は、完了後に **Downloaded archives need manual extraction or installer run** と **Open folder** を表示します。自分で展開するか公式インストーラーを実行し、実際に起動できるゲームディレクトリを Manager に追加してください。インストーラーや DRM の回避は行いません。


## DLsite ダウンロード

DLsite へのサインインにはブラウザー Cookie を使います。サインインページを開き、CAPTCHA や追加認証をブラウザーで完了してから、セッション Cookie を Manager に貼り付けます。セッションはプラットフォームの秘密情報ストアだけに保存されます。ライブラリには DLsite Play の購入作品を表示し、DLsite がアカウント向けに提供する PC 版ファイルだけを取得します。Play の閲覧用・メディア用最適化ファイルはゲームとしてインストールしません。ZIP はパス安全性を検査して展開します。RAR と自己解凍インストーラーは変更せず保存し、手動での展開またはインストールが必要です。ダウンロードした実行ファイルを Manager が起動することはありません。調査した API からはインストール済みビルドを特定できないため、更新状態は不明として表示します。

ダウンロード計画を解決できない作品は、サインイン済みブラウザーで操作を再現し、応答本文を含む HAR をエクスポートしてください。`https://play.dlsite.com/api/v3/download?workno=<購入済み作品番号>` から始め、リダイレクト先と `/home/download`、`/home/serial`、分割ファイル一覧の各リクエストを含めます。共有前に Cookie、シリアル番号、署名付き URL の token を削除してください。HAR をコミットしないでください。

## 互換性とメタデータ

既定のメタデータソースは次のとおりです。

`https://project-shinkirou.github.io/data/shinkiemu/v1/`

設定ページでネットワーク接続の許可と手動同期を行えます。破損した、または検証に通らなかったスナップショットが有効なキャッシュを上書きすることはありません。レポートを見るときは、VNDB のリリース rID、コア、プラットフォーム、アーキテクチャ、desktop/device/simulator のバリアントがすべて一致しているかを確認してください。別のプラットフォームやアーキテクチャの結果は、現在の環境には当てはまりません。再現可能な観察結果は [issue フォーム](https://github.com/Project-Shinkirou/ShinkiEMU/issues/new/choose)から報告できます。

## パッチ

レビュー済みの **Luau レシピ**は、ユーザーが明示的に選択した場合にのみ実行されます。パッチ画面の既定は**新しいディレクトリ**で、元のゲームは変更しません。**その場で上書き**を選ぶと、変換結果を専用の一時領域に作成し、変更・削除する元ファイルを `<game>/.shinki/backup/<id>/` に退避します。`manifest.json` にファイルのハッシュを記録し、適用後は同じゲームを再検出します。**最新のパッチを復元**する前にはパッチ適用後のファイルを照合するため、ユーザーが編集したファイルは上書きされません。レシートは `<game>/.shinki/patch-result.json` に保存されます。添付ファイル付きの external/hosted パッチは HTTPS でダウンロードでき、Manager はサイズと SHA256 を確認したうえで `<game>/.shinki/patch/` に保存し、パッチ入力先に設定します。ダウンロードだけで添付ファイルが実行されることはありません。実行できるのは別途選んだ信頼済み Luau レシピだけです。ライセンス、許諾根拠、対象リリースを確認してください。リリース一覧が空なら「対象リリース未限定」であり、全版での検証済みを意味しません。詳しくは [Metadata](metadata.md) を参照してください。

## データとセーブ

ShinkiEMU は新しいプラットフォーム別のアプリケーションデータディレクトリを使い、その場所は設定から開けます。デスクトップでは `SHINKI_EMU_DATA_DIR` で絶対パスを指定できます。Android ではアプリ専用ディレクトリを使います。名称変更前のアプリケーションデータベース、キャッシュ、製品独自のセーブは自動では取り込まれません。この切り替えで元のゲームのインストールや市販版のセーブデータが変更されることはありません。

セーブの扱いはコアごとに決まります。Musica の独自スロットは `<game>/.shinki/musica/saves/` に置きます。初回利用時に旧 `.shinki-musica/saves/` のファイルを移動し、新しい場所の既存ファイルは上書きしません。その後の読み込み先は新しい場所だけです。ReMinori は独立したセーブルートを使います。同じファミリーのコア同士でもセーブを流用しないでください。データのバックアップやコア変更の前に、実行中のセッションを終了してください。
