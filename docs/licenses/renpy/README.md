# Ren’Py source and relinking

This package is a local candidate. Public distribution of the standalone Ren’Py core and of the Android Manager APK that embeds Ren’Py is blocked until the matching source and relinking material is available and verified. The Windows Manager does not embed Ren’Py.

Ren’Py and its dependencies retain their own licenses. The desktop `librenpython` library includes LGPL components such as FFmpeg and FriBidi; the outer shared library does not make those components permissive. The Python runtime includes chardet (LGPL) and certifi (MPL-2.0). Keep the official `LICENSE-RenPy.txt`, the component notices (including `python/chardet/LICENSE` and `python/certifi/LICENSE`), and the font licenses shipped beside the fonts. See the [upstream license inventory](https://www.renpy.org/doc/html/license.html). ShinkiEMU does not restrict modification of LGPL components, compatible runtime replacement or reverse engineering to debug those modifications.

## Material to verify before enabling publication

- **Windows x64 standalone:** From the pinned `renpy-build` tree on Ubuntu 24.04, put the exact upstream Ren’Py tree in `renpy/` and use the Windows x86_64 configuration described in its `README.rst`. Keep the generated build/link commands for `tasks/ffmpeg.py`, `tasks/fribidi.py` and `tasks/renpython.py`, the MinGW/LLVM and Python toolchain identities, and the modified and unmodified source inputs. Rebuild `librenpython.dll` with a modified LGPL library and check its exports and the compatible `libpython3.12.dll` ABI against the shipped DLLs. Replace the runtime DLLs in a copy of the staged core and verify it loads with the separately built display override and adapter. The pinned adapter's `shinki/CMakeLists.txt` links those pieces through SDK-derived import libraries; the stock SDK hash check is for preparing the original package, so perform replacement in the staged copy. For each other supported desktop platform supply and validate the analogous target build/link and runtime replacement path.
- **Android Manager (`arm64-v8a` and `x86_64`):** The LGPL objects are inside the Manager library; dropping in a shared library does not replace them. On Ubuntu 24.04, run the locked adapter's `shinki/android_runtime.py` with `--build-root` at the pinned `renpy-build`, `--target` set to `aarch64-linux-android` or `x86_64-linux-android`, `--output` set to a fresh ABI-specific directory and `--host-python` pointing to CPython 3.12.7 with Cython 3.2.4. Use the r29 Linux NDK and Cubism header SDK from `shinki/sdk.json`; the product links with r30 at API 28. Retain the runtime's headers, archives, `shinki-renpy-runtime.pc`, and `Resources/`. Supply the product's exact source and build scripts or the relinkable objects/archives for the rest of `libshinki_emu_manager.so`, the ordered final linker inputs/flags (including any symbol rewriting), and the APK assets and assembly instructions. Verify a clean rebuild or relink with at least one modified LGPL library for each ABI using an independently test-signed APK. Use `RENPY_STATIC_ROOT` to select the rebuilt runtime for the matching ABI; the one-ABI `package --qa-single-abi` path can exercise it. The production signing key is not part of the relink material. Do not distribute a restricted SDK or a game-supplied Cubism binary as source material.

For a public asset, record its hash, platform/ABIs, exact source links, all required build inputs, and where recipients can retrieve the tested relink material. Check those links and the modified-library procedure from a clean environment before removing the publication block. No source ZIP is promised by the packager.
